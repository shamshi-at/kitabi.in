# Kitabi is a public reference site. Everything here is meant to be found —
# by search engines and by AI answer engines alike. Nothing is disallowed.
#
# This file used to be only half the story: Cloudflare's "Managed robots.txt"
# setting PREPENDED a block that disallowed GPTBot, ClaudeBot, CCBot,
# Google-Extended, Bytespider, meta-externalagent, Amazonbot and
# Applebot-Extended, and set Content-Signal: ai-train=no. It could not be
# overridden from here — in robots.txt a named User-agent group beats "*", so
# the managed block decided for every crawler it named regardless of what this
# file said.
#
# That setting was turned OFF on the kitabi.in zone (AI Crawl Control →
# Overview) on 4 Aug 2026, deliberately. Verified in the served response: no
# managed block, no Disallow, no Content-Signal. This file is now the whole
# story again.
#
# The reasoning, so nobody re-enables it by reflex: a reference site whose value
# is content nobody else has WANTS to be citable by AI answer engines, because
# that is a real and growing discovery channel. The distinction worth keeping in
# mind is between crawlers that TRAIN on content (GPTBot, CCBot,
# Google-Extended) and those that FETCH it to answer a question with attribution
# (OAI-SearchBot, PerplexityBot, ClaudeBot, Claude-SearchBot). Blocking the
# first while allowing the second is a coherent position worth revisiting; what
# was happening before was blocking both by inheritance, which nobody chose.
#
# Note this file governs kitabi.in ONLY — robots.txt is per-host. The other two
# hosts are deliberately the opposite of this one: admin.kitabi.in and
# api.kitabi.in both serve "Disallow: /" and stamp X-Robots-Tag on every
# response (api/app/core/noindex.py, admin/console/noindex.py). An admin login
# in a search index gains nothing and invites credential stuffing; an indexed
# API endpoint is free reconnaissance. Only kitabi.in is meant to be found.

User-agent: *
Allow: /
# Faceted browse and search are `noindex, follow` already — they explode
# combinatorially and the hubs (/genre/…, /language/…, /translations) are the
# canonical entry points, all in the sitemaps. noindex does not stop the
# fetching, though: a crawler still renders every filter combination to read
# the tag, then follows the chips into the next one. That walk was ~3,700
# origin renders a day, each a set of Supabase queries whose bytes out are
# metered (7 Sep 2026). Bare /browse and /search stay open; only the
# parameterised forms are closed.
Disallow: /browse?
Disallow: /search?

Sitemap: https://kitabi.in/sitemap.xml
Sitemap: https://kitabi.in/sitemaps/index.xml
