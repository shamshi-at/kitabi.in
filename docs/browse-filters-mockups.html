The browse filters, organised

Owner report on the shipped panel: "everything is mixed." Correct — five different jobs (sort · type · genre · language · length) all wear the same pill, so the open panel reads as a tag cloud. Three directions below, all zero-JS and server-rendered like everything else on the site. The collapsed bar from yesterday stays exactly as it is in every one of them — these mockups reorganise what you see after you tap "Filter & sort".

The problem A · Facet cards B · Library rail C · Five doors ★
F0 · shipped today

Why it feels mixed

Four defects, one root cause — one visual voice for five different controls: ① a sort (pick exactly one) is drawn identically to a facet (narrows the list), so the eye can't parse what kind of choice each row offers; ② the rows have no containment — genre wraps to a second line mid-list and the labels float loose; ③ counts compete with names ("Literary fiction 229" is one grey blob); ④ the panel stretches edge-to-edge at desktop widths, so every row is long, ragged, and differently so.

What must survive any redesign: plain links (crawlable, no-JS), aria-current on the active choice, the composable URLs, the collapsed one-line bar with removable ✕ chips, and the count line. These are behaviours, not looks.
Direction A

Facet cards — four titled boxes and a real sort control

Sort stops being chips. It becomes a segmented control on its own line — joined buttons, one active — which is the universal shape for "exactly one of these". The four facets each get a titled card: Type, Genre, Language, Length. Counts move into small gold badges so names read as names. The genre card shows the eight biggest and opens the full list through an "All 33 →" door to /genres. Cards give the panel a grid rhythm at any width.

Direction B

The library rail — facets live beside the books, not above them

The reference-site answer (this is what "IMDB for books" implies). A permanent left rail holds the facets as titled groups of rows, not pills — name left, count right-aligned in its own quiet column, active row oxblood with its ✕. Vertical lists scan; 33 genres become a readable column with a "Show all" tail instead of a wrapping cloud. Sort moves to the results header next to the count, where every list on the web puts it. Nothing sits above the books at all — the grid starts at the top.

Direction C · recommended

Five doors — one small panel per facet, never a wall

The bar opens into a row of five labelled doors — Sort · Type · Genre · Language · Length — each a <details> that opens a small popover with only that facet, drawn as B's row-list (names left, counts right, two columns for genre). One door open at a time via the native name= attribute — still zero JS. An active door turns oxblood and carries its value in the label ("Genre · History"), so the closed state reads as a sentence: what you're seeing, in five words. The panel can never become a wall because no more than one facet is ever visible.

Why this is the recommendation. It keeps yesterday's win (nothing tall above the books, ever), fixes the mixing completely (each facet in its own labelled door; sort visually distinct and worded as a value), scales to 33 genres (a two-column list with aligned counts, not a wrapping cloud), reads as a sentence when closed ("Sort · Top rated | Genre · History | Language · Malayalam"), and is one layout for desktop AND mobile. Native <details name="facet"> gives one-open-at-a-time with zero JS. B remains the better answer if you want the full reference-site feel and accept two layouts; A is the fallback if you want tomorrow's smallest diff.
