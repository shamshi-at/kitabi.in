Notes, while the clock runs

Three faults from one report (14 Aug 2026): a note written on one device takes up to fifteen minutes to reach the other, the count beside “Note a thought” doesn’t look like a door — so nobody discovers that tapping it opens what they already wrote — and once the editor is open, the notes from this same sitting are nowhere to be seen.

The problem

One pill, two tap targets, no labels

The control is a single rounded pill, and the two halves do different things: the words open a blank editor, the small grey number opens the list of notes you’ve already written. Nothing marks the seam. A number in a chip reads as a badge — a status, like an unread count — and badges are not usually buttons.

Direction B

Show the notes instead of counting them

The count exists because the notes are hidden. Show the notes and the count stops being needed: one line each, page number first, newest last — the shape they already have in the book page’s journal (N4). The pill goes back to doing exactly one thing.

The editor

What you already wrote, where you’re writing

The third fault, and the one that costs a reader most: the editor is a page (the scarce resource while reading is room to write, N2), and from it the sitting’s earlier notes are gone — so you can’t check whether you already caught a thought, and you can’t continue one. It sits under the composer as a collapsed disclosure: present, named, and not competing with the keyboard.

Collapsed, and the sync made visible The disclosure closes while typing. The one line about the other device is worth saying once, on save — a note that silently takes fifteen minutes to appear elsewhere reads as a note that was lost.

The sync half

Notes are already a synced entity — reading_notes is in the sync engine, and the writing device pushes on every enqueue. What’s missing is the other direction: a device only pulls on foreground, on reconnect, or on the 15-minute workmanager tick, so a note can sit invisible on the second phone for a quarter of an hour. Exactly the timer problem, and it now has the same answer: the FCM path added on 14 Aug already nudges the other device to re-read for a reading event, and a note push is the same shape — one silent data message, and the receiving device drains the queue it already knows how to drain. No new sync mechanism, no new bill.

What I’d build

  • B for the face, plus the editor disclosure. A shows the count more honestly; B removes the reason there was a count. The two faults share one root — the notes are hidden — so the fix that shows them fixes both.
  • Cap at three with an honest “All 7 ›”, so a long sitting never pushes Stop & log around.
  • Silent push on note save, reusing fcm_client.send(silent=True).
  • The “Saved & synced” line is deliberately not a per-note status: it says the thing once, and never invents a state the app can’t actually observe offline.
